# 收款码图片（手动收款版）

## 现状：全是占位图，不要扫码付款
- `wechat-full.svg` / `alipay-full.svg`：全份报告 ¥19.9 的微信 / 支付宝收款码占位图
- `wechat-single.svg` / `alipay-single.svg`：单维报告 ¥9.9 的微信 / 支付宝收款码占位图
- 占位图里没有二维码，只有一句“此处贴真实收款码”和“占位图 · 请勿扫码付款”，扫了也付不了钱。**收入仍是 0，没有编造任何收款。**
- 页面优先显示同名 `.png` 真码，没有真码时才回退显示这里的 `.svg` 占位图（见 `components/PaywallCard.tsx` 的 `QrImage`）。

## 换成 sir 的真码（只换图，不改代码）
1. sir 在微信里打开“我 → 服务 → 收付款 → 二维码收款”，保存自己的微信收款码图片；支付宝里打开“收付款 → 二维码收款”，保存支付宝收款码图片。
2. 把真码按金额和渠道分别命名为 `.png`，放到这个目录，与占位图同名（只改后缀）：
   - 全份 ¥19.9 的微信码 → `wechat-full.png`
   - 单维 ¥9.9 的微信码 → `wechat-single.png`
   - 全份 ¥19.9 的支付宝码 → `alipay-full.png`
   - 单维 ¥9.9 的支付宝码 → `alipay-single.png`
   - 如果真码是 JPG，先转成 PNG 再放进来；文件名必须和上面完全一致，代码只认这 4 个名字。
   - 微信和支付宝的收款码本身不带固定金额，同一张码可用于两个档位；如果 sir 只给一张微信码、一张支付宝码，就把同一张图复制成两份（full 和 single 各一份），页面会按所选档位显示对应金额文字。
   - 注意：PNG 是二进制文件，推送工具只接受 UTF-8 文本，**不要走 snapshot 推送**；真码 PNG 由主代理在 Render 部署后另外处理，或等 sir 发图后由主代理通过浏览器/其他方式放到服务器上。占位 SVG 可以正常推送。
3. 换好后推到 `commercial` 分支，Render 自动重新部署，线上付费页就显示真码了。
4. 注意：微信/支付宝个人收款码只适合这种手动核对过渡；长期自动收款仍需个体户执照接官方接口。
